# DeepSeek-V3 `test_decoder_mlp` — modeled in tt-prism

A tt-prism model of what
`TT_METAL_SLOW_DISPATCH_MODE=1 pytest models/demos/deepseek_v3_b1/tests/unit_tests/test_decoder_block.py::test_decoder_mlp`
actually runs, built from a static analysis of the `aho/sdpa-ops` branch of tt-metal.

> **It can't run on a single Wormhole card.** The test is hardwired for **8 Blackhole
> chips in a 4×2 mesh** (`@requires_grid_size((13,10))`, `MeshShape(4,2)`,
> `silicon_arch_blackhole`; `test_decoder_block.py:859,877,892`). So this is a
> faithful *model*, with proportional (not measured) durations.

Despite the `_mlp` name, the test runs the **full DecoderBlock**: MLA attention
(including **flash SDPA**) **and** the FFN. `_mlp` only means the FFN runs *dense*
(`enable_routing=False`), tiling the 18432 intermediate over the MoE kernel as
8×2048 "experts" + a shared expert.

## The two models

### 1. `sdpa_chunk.yaml` — the op the analysis centered on
`compute_sdpa_chunk` (`kernel_includes/.../compute_kernel_api/sdpa.h:250`, driven by
`micro_ops/sdpa/kernels/sdpa_compute.cpp`): flash online-softmax over K/V chunks.
Per chunk: **QK^T (FPU) → reduce-max (SFPU) → bcast-sub (FPU) → exp/correction
(SFPU+FPU) → PV matmul (FPU) → reduce-sum (SFPU)**, then a final recip/normalize +
pack. Accumulators (running max/sum, output) live in **DEST for the whole op**; each
step is a tight FPU↔SFPU semaphore ping-pong, so the timeline is largely serial —
which the schedule makes obvious. Modeled as 3 chunks + normalize on one core.

```bash
tt-prism serve examples/deepseek/sdpa_chunk.yaml     # /flow → "Single op" = the dataflow
tt-prism schedule examples/deepseek/sdpa_chunk.yaml  # FPU/SFPU serialization in the timeline
```

### 2. `decoder_mlp_chip.yaml` — the whole test (8-chip mesh)
Generated by `gen_decoder_mlp.py`. Each of the 8 chips runs the same SPMD pipeline;
the four cross-chip collectives are `noc` dependencies you can step through in the
flow view's **Chip** mode.

```bash
tt-prism serve examples/deepseek/decoder_mlp_chip.yaml
#   http://127.0.0.1:8765        Gantt — 8 chips × TRISC0/1/2 lanes, grouped by chip
#   http://127.0.0.1:8765/flow   "Single op" → open `flash_mla SDPA` etc.; toggle "Chip"
#                                 to step the 24 NoC interactions (4 collective phases)
# regenerate after edits:  PYTHONPATH=src python examples/deepseek/gen_decoder_mlp.py
```

## What the decoder does (op-DAG, per chip)

**Phase A — MLA attention** (`fused_ops/attention_block`):
`rmsnorm_in → q_proj → kv_a/b_proj → rope+kv_cache → flash_mla SDPA →
sdpa_reduce_to_all → post_sdpa (kv_b2 + o_proj)`.

**Phase B — dense MLP** (`fused_ops/moe`, routing off):
`rmsnorm_mlp → gate_up_proj+silu → down_proj + shared_expert → combine`.

**The 4 cross-chip collectives (fabric / NoC):**
| Phase | Collective | Axis | Modeled as |
|---|---|---|---|
| start | input **broadcast** | sender chip (1,0)=dev2 → all 8 | 7 noc edges into `rmsnorm_in` |
| attn | **SDPA reduce** | across the 4 rows (seq-parallel, axis 0) | 6 noc edges into `sdpa_reduce` |
| attn | o_proj **all-reduce** | across the 2 cols (tensor-parallel, axis 1) | 4 noc edges into `o_proj` |
| end | **reduce-to-one** | tree to root chip (1,1)=dev3 | 7 noc edges into `combine` |

Mesh layout (x=col, y=row; device idx = row·2+col): chip2=(1,0) is the input
**sender**, chip3=(1,1) is the reduce **root** where the test reads the result.

## Fidelity & caveats
- **Granularity:** ops are at the fused-op / phase level (≈12 per chip), not every
  micro-op. Within-chip gathers/mcasts are folded into the consuming op (they're NoC
  dataflow, not compute). Cross-*chip* movement is shown as `noc` deps.
- **Durations** are proportional estimates (SDPA: QK∝C·K, PV∝K·V, exp∝C; matmuls
  dominate FFN). Replace with measured values when available (e.g. from a ttsim or
  tracy run on Blackhole hardware).
- **Engine mapping** follows the kernels: TRISC0=UNPACK, TRISC1=FPU, TRISC2 issues
  **both** SFPU vector ops and PACK (so SFPU/PACK share a lane).
